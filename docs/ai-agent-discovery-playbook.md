**منابع:** پرزنتیشن Empathy Technologies (M365 Copilot) + کال Discovery Chetu با ITneck (Agentic + RAG / Track2Ai)

## ۳. سوالات Discovery (کامل)

برای هر سوال: **بهترین جواب** = سیگنال سبز برای ساخت؛ **پرچم قرمز** = ریسک یا اسکوپ اشتباه.

### بلوک A — کسب‌وکار و درد (Track2Ai Step 01)

#### A1. بزرگ‌ترین درد تکراری چیست که تیم وقت می‌سوزاند؟

- **بهترین جواب:** یک فرآیند مشخص با حجم و هزینه قابل‌اندازه‌گیری (مثلاً «حدود ۵۰ تیکت Tier-1 در روز، میانگین ۲۰ دقیقه
  پاسخ»).
- **پرچم قرمز:** جواب مبهم مثل «می‌خواهیم AI داشته باشیم» بدون فرآیند، حجم، یا مالک.

#### A2. موفقیت در ۹۰ روز چه شکلی است؟ چه KPIای اندازه‌گیری می‌کنید؟

- **بهترین جواب:** عدد مشخص — زمان پاسخ، نرخ حل خودکار، ساعات صرفه‌جویی، کاهش backlog، رضایت کاربر.
- **پرچم قرمز:** «هوشمندتر شویم» بدون معیار؛ یا KPIهایی که داده برای اندازه‌گیری‌شان وجود ندارد.

#### A3. کدام دپارتمان اولویت ۱ است و اسپانسر اجرایی کیست؟

- **بهترین جواب:** یکی از ۶ حوزه بالا + نام فرد با قدرت تأیید بودجه و UAT.
- **پرچم قرمز:** «همه دپارتمان‌ها هم‌زمان»؛ یا اسپانسر فقط IT بدون مالک کسب‌وکار.

#### A4. قبلاً AI / Copilot / چت‌بات امتحان کرده‌اید؟ چه چیزی کار کرد یا شکست خورد؟

- **بهترین جواب:** تجربه شفاف + درس‌آموخته؛ یا «نه، ولی داده و فرآیند آماده است».
- **پرچم قرمز:** شکست قبلی بدون تحلیل علت؛ انتظار جادو بدون تغییر فرآیند.

#### A5. چه چیزی را عمداً در v1 نمی‌خواهید؟ (ضد دامنه)

- **بهترین جواب:** لیست صریح خارج از اسکوپ (مثلاً «بدون نوشتن در ERP»، «بدون مشتری خارجی در فاز ۱»).
- **پرچم قرمز:** «همه‌چیز را می‌خواهیم از روز اول».

---

### بلوک B — دامنه ایجنت و رفتار Agentic + RAG

#### B1. کاربر نهایی کیست و از کدام کانال استفاده می‌کند؟

- **بهترین جواب:** نقش مشخص (کارمند داخلی / مشتری / هر دو) + کانال اصلی (Teams / SharePoint / Outlook / وب).
- **پرچم قرمز:** «همه» بدون persona؛ یا کانال‌هایی خارج از M365 بدون بودجه یکپارچه‌سازی.

#### B2. ایجنت فقط پاسخ بدهد یا اقدام هم بکند؟ مرز تأیید انسان کجاست؟

- **بهترین جواب:** تفکیک واضح خواندن vs نوشتن؛ human-in-the-loop برای اقدامات حساس (تأیید، پرداخت، تغییر دسترسی).
- **پرچم قرمز:** اقدام خودکار روی داده حساس بدون مسیر تأیید؛ یا عدم تمایز بین Q&A و automation.

#### B3. دانش ایجنت از کجا می‌آید؟ (منابع RAG)

- **بهترین جواب:** منابع محدود و باکیفیت — مثلاً ۲–۵ سایت/کتابخانه SharePoint یا OneDrive با permission واقعی و مالک
  محتوا.
- **پرچم قرمز:** «همه فایل‌های شرکت»؛ درایوهای شخصی نامرتب؛ PDFهای اسکن‌شده بدون OCR؛ بدون مالک به‌روزرسانی.

#### B4. وقتی سوال خارج از دامنه است، ایجنت چه کند؟

- **بهترین جواب:** escalate به انسان + لاگ؛ پیام شفاف «نمی‌دانم / به X ارجاع می‌دهم» — نه حدس زدن.
- **پرچم قرمز:** اجبار به همیشه جواب دادن؛ نبود مسیر escalation.

#### B5. سه سؤال واقعی که امروز از انسان می‌پرسند + جواب ایده‌آل چیست؟

- **بهترین جواب:** ۳ جفت سؤال/جواب واقعی از تیکت، ایمیل، یا FAQ فعلی (بهترین ورودی prompt و ارزیابی RAG).
- **پرچم قرمز:** نمونه ساختگی یا خیلی کلی؛ نبود منبع پاسخ در اسناد موجود.

#### B6. آیا به چند ایجنت هماهنگ (orchestration) نیاز دارید یا یک ایجنت کافی است؟

- **بهترین جواب:** برای v1 معمولاً یک ایجنت با دامنه باریک؛ orchestration فقط اگر فرآیند چندتخصصی اثبات‌شده باشد.
- **پرچم قرمز:** طراحی multi-agent قبل از اثبات یک use case.

### بلوک C — داده، امنیت، آمادگی M365 (Track2Ai Step 02)

#### C1. وضعیت لایسنس Microsoft 365 و Copilot چیست؟

- **بهترین جواب:** وضعیت شفاف (چه کسی لایسنس دارد / ندارد) + آمادگی خرید بعد از Discovery در صورت نیاز.
- **پرچم قرمز:** فرض «خودکار همه دارند»؛ یا مسدود بودن خرید لایسنس بدون timeline.

#### C2. چه الزامات امنیتی / compliance دارید؟ (GDPR، SOC، HIPAA، داده محلی، …)

- **بهترین جواب:** نیاز مشخص + ترجیح داده داخل tenant / کنترل دسترسی مبتنی بر permission موجود M365.
- **پرچم قرمز:** «باید کاملاً امن باشد» بدون استاندارد؛ یا داده حساس در منابع بدون کنترل دسترسی.

#### C3. چه کسی دسترسی SharePoint / منابع دانش را تأیید می‌کند؟ (مالک داده)

- **بهترین جواب:** نام فرد یا نقش (IT + مالک کسب‌وکار) که در همان هفته اول دسترسی آزمایشی می‌دهد.
- **پرچم قرمز:** «بعداً می‌فهمیم»؛ سیاست‌هایی که مانع هرگونه دسترسی به سند می‌شود بدون مسیر استثنا.

#### C4. محیط Dev / UAT / Production جدا دارید یا موافقت می‌کنید قبل از prod تست شود؟

- **بهترین جواب:** بله جداست؛ یا موافقت کتبی با محیط تست و UAT قبل از انتشار.
- **پرچم قرمز:** اصرار به استقرار مستقیم روی production بدون UAT.

#### C5. چه سیستم‌هایی باید وصل شوند؟ (CRM، ERP، تیکتینگ، …)

- **بهترین جواب:** لیست کوتاه با اولویت (حداکثر ۱–۲ اتصال در PoC).
- **پرچم قرمز:** ده سیستم هم‌زمان در فاز اول؛ API بدون owner یا بدون مستند.

#### C6. حجم تقریبی اسناد/داده و کیفیت آن چگونه است؟

- **بهترین جواب:** برآورد واقع‌بینانه + پذیرش پاکسازی/ساختاردهی در Discovery یا ابتدای PoC.
- **پرچم قرمز:** داده درهم بدون بودجه پاکسازی؛ انتظار دقت بالا روی دانش نامرتب.

### بلوک D — PoC، تجاری، تحویل (Empathy Phase 1–2 + Track2Ai Step 03)

#### D1. کدام ۲–۳ use case برای PoC اولویت دارند و معیار پذیرش UAT چیست؟

- **بهترین جواب:** اولویت‌بندی‌شده با معیار قابل‌اندازه‌گیری (مثلاً «در ۲۰ سؤال طلایی، ≥۸۰٪ پاسخ درست با citation»).
- **پرچم قرمز:** PoC بدون معیار پذیرش؛ یا ده use case «همه فوری».

#### D2. بودجه و تایم‌لاین مطلوب چیست؟

- **بهترین جواب:** بازه واقعی — Discovery کوتاه (روزها تا ۲ هفته) + PoC حدود ۳–۶ هفته؛ بودجه هم‌تراز فازها.
- **پرچم قرمز:** «تا هفته بعد production کامل»؛ بودجه صفر برای داده/آموزش/adoption.

#### D3. بعد از go-live مالک ایجنت کیست؟ تیم داخلی یا managed services؟

- **بهترین جواب:** مالک مشخص + مسیر پشتیبانی (داخلی آموزش‌دیده یا retainer).
- **پرچم قرمز:** «شما بسازید و بروید» بدون مالک محتوا یا عملیات.

#### D4. مدل همکاری ترجیحی چیست؟

- **بهترین جواب:** Discovery ثابت‌قیمت → PoC با معیار موفقیت → Rollout؛ IP و دسترسی مطابق MSA.
- **پرچم قرمز:** تعهد Rollout کامل قبل از Discovery؛ قفل قرارداد بلند بدون امکان خروج.

#### D5. معیار رد / توقف PoC چیست؟

- **بهترین جواب:** آستانه توافق‌شده — مثلاً اگر دقت زیر X٪ یا escalation بالای Y٪ بود، بازنویسی دامنه یا توقف.
- **پرچم قرمز:** هیچ معیار شکستی تعریف نشده؛ فشار برای «قبول کردن» نتیجه ضعیف.

#### D6. چه ابزارهای همکاری و cadence ارتباطی می‌خواهید؟

- **بهترین جواب:** Teams/Slack + جلسات هفتگی دمو + مالک پاسخ‌گو برای تصمیم‌های مسدودکننده.
- **پرچم قرمز:** عدم دسترسی به کاربران کسب‌وکار برای تست؛ تصمیم‌گیر همیشه غایب.

## ۵. چک‌لیست خروجی جلسه Discovery

جلسه فقط وقتی «تمام» است که موارد زیر پر شده باشند:

### ۵.۱ خروجی کسب‌وکار

- [ ] بیانیه درد در یک جمله + حجم/هزینه تقریبی
- [ ] KPIهای ۹۰روزه (حداکثر ۳ متریک)
- [ ] دپارتمان اولویت ۱ + نام اسپانسر اجرایی
- [ ] ضد دامنه v1 (لیست خارج از اسکوپ)

### ۵.۲ خروجی محصول ایجنت

- [ ] Persona کاربر نهایی
- [ ] کانال انتشار (Teams / SharePoint / Outlook / …)
- [ ] حالت: Q&A فقط / Q&A + اقدام (با human-in-the-loop)
- [ ] منابع RAG اولویت‌دار (نام سایت/کتابخانه) + مالک داده
- [ ] رفتار خارج از دامنه (escalation path)
- [ ] حداقل ۳ جفت سؤال/جواب نمونه واقعی

### ۵.۳ خروجی فنی و آمادگی

- [ ] وضعیت لایسنس M365 / Copilot
- [ ] الزامات compliance (در صورت وجود)
- [ ] توافق محیط تست قبل از production
- [ ] اتصالات خارجی برای PoC (۰–۲ مورد) یا «هیچ»

### ۵.۴ خروجی PoC و تجاری

- [ ] ۲–۳ use case رتبه‌بندی‌شده برای PoC
- [ ] معیار پذیرش UAT (عدد یا چک‌لیست تست)
- [ ] معیار رد / توقف PoC
- [ ] بازه بودجه و تایم‌لاین تقریبی
- [ ] مالک پس از go-live
- [ ] next step زمان‌بندی‌شده (پیشنهاد ثابت‌قیمت Discovery یا kickoff PoC)

### ۵.۵ ریسک‌های ثبت‌شده

- [ ] کیفیت داده / دسترسی اسناد
- [ ] نبود اسپانسر یا تصمیم‌گیر
- [ ] لایسنس یا سیاست امنیتی مسدودکننده
- [ ] انتظارات غیرواقعی زمان/دقت

## ۶. معیار پذیرش و رد PoC (پیشنهادی پیش‌فرض)

این اعداد را در جلسه با مشتری تنظیم کنید؛ پیش‌فرض پیشنهادی برای ایجنت دانش‌محور (RAG) داخل M365:

| معیار                                            | پذیرش (Pass)                         | رد / بازنویسی (Fail)    |
|--------------------------------------------------|--------------------------------------|-------------------------|
| دقت پاسخ روی مجموعه طلایی (۲۰–۵۰ سؤال)           | ≥ ۸۰٪ پاسخ قابل‌قبول با منبع درست     | < ۶۵٪                   |
| hallucination خطرناک (ادعای غلط به‌جای «نمی‌دانم») | ≤ ۵٪                                 | > ۱۵٪                   |
| نرخ escalation درست روی خارج‌ازدامنه              | ≥ ۹۰٪                                | < ۷۰٪                   |
| رعایت permission (بدون نشت به کاربر غیرمجاز)     | ۱۰۰٪ در تست                          | هر مورد نشت = Fail فوری |
| زمان پاسخ قابل‌قبول کاربر                         | توافق با مشتری (مثلاً < ۱۰ ثانیه P95) | مداوم خارج از آستانه    |
| UAT امضاشده توسط اسپانسر کسب‌وکار                 | بله                                  | خیر                     |

**قانون طلایی:** بدون مجموعه سؤال طلایی و بدون مالک داده، PoC را شروع نکنید.

## ۸. پیشنهادهای عملی فراتر از اسلایدها

اسلایدهای Empathy و Chetu پرسش‌نامه صریح ندارند؛ این چهار مورد را همیشه اضافه کنید:

1. **ضد دامنه** — بدون آن، اسکوپ می‌ترکد.
2. **مالک داده SharePoint** — بدون او RAG در M365 گیر می‌کند.
3. **۳ مکالمه واقعی** — بهترین ورودی طراحی و تست.
4. **معیار رد PoC** — جلوی پذیرش نتایج ضعیف را می‌گیرد.
